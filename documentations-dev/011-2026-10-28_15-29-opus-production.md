# Phase 6 : Production (envoi des fichiers par nginx, sauvegardes, déploiement par GitHub)

> Date : 28 octobre 2026, 15 h 29

## Objectif
Préparer la mise en ligne sur le VPS : fichiers médias envoyés par nginx, sauvegardes automatiques,
configuration du serveur, et déploiement exclusivement par GitHub après des tests verts.

## Actions realisees

### 1. Envoi des médias par nginx (X-Accel-Redirect)
**Fichiers :** `src/Controller/MediaFileController.php`, `src/Service/MediaStorage.php`, `docker/nginx/default.conf`
- Quand `MEDIA_X_ACCEL_PREFIX` est défini, Symfony vérifie toujours les droits (`MediaVoter`), puis répond par
  `X-Accel-Redirect: /_media_internal/…` sans lire le fichier ; nginx l'envoie depuis une location `internal`.
- PHP-FPM est libéré immédiatement, même pour une vidéo de 256 Mo ; nginx gère `Range` et `ETag`.
- Activé aussi dans le Docker de dev, pour que le dev se comporte comme la prod. Vide : `BinaryFileResponse` comme avant.
- `MediaStorage::getRelativePath()` refuse tout chemin hors du stockage et encode chaque segment.

### 2. Sauvegardes
**Fichier :** `bin/backup.sh`
- Base : `mariadb-dump --single-transaction` compressé, écrit dans un fichier temporaire puis renommé.
- Médias : instantanés `rsync --link-dest` : chaque sauvegarde est complète, mais seuls les nouveaux fichiers prennent de la place.
- Rotation sur 14 jours, `umask 077`, mot de passe lu dans un fichier d'identifiants (jamais sur la ligne de commande),
  compte MariaDB de sauvegarde en lecture seule.

### 3. Déploiement par GitHub
**Fichiers :** `.github/workflows/ci-deploy.yml`, `bin/deploy.sh`
- Préprod : à chaque push et pull request, tests sur GitHub Actions (PHP 8.3, MariaDB 11.4, ffmpeg) : `composer validate`,
  lint YAML / Twig / conteneur, migrations, `doctrine:schema:validate`, PHPUnit.
- Prod : **jamais automatique**. Déploiement lancé à la main (« Run workflow », `workflow_dispatch`) sur `main` ;
  les tests sont rejoués dans le même lancement, puis connexion SSH au VPS avec la clé de l'environnement `production`.
- La clé est limitée côté serveur par `command="/var/www/sarah/bin/deploy.sh"` : elle ne peut que transmettre un commit.
- `deploy.sh` n'accepte qu'un identifiant de commit de 40 caractères, appartenant à `origin/main` ; puis sauvegarde,
  `git checkout`, `composer install --no-dev`, `dump-env prod`, assets, migrations, cache, rechargement de PHP-FPM.
- Un seul déploiement à la fois (verrou `flock` côté serveur, `concurrency` côté GitHub) ; empreinte SSH du serveur
  fixée dans les secrets (pas de `StrictHostKeyChecking=no`).

### 4. Configuration du serveur
**Fichiers :** `docs/devops/prod/nginx-sarah.conf`, `docs/devops/prod/php-fpm-sarah.conf`, `docs/devops/prod/env.local.example`
- nginx : HTTPS (Let's Encrypt), HSTS et en-têtes de sécurité (répétés dans la location interne, car `add_header` ne s'hérite pas),
  fichiers cachés et PHP autres que `index.php` refusés, assets en cache long.
- PHP-FPM : pool dédié sous l'utilisateur `sarah`, limites d'envoi identiques au dev, opcache sans vérification des fichiers.
- Journaux de prod : fichiers tournants dans `var/log/` (30 jours) au lieu de `stderr`.

### 5. Procédure
**Fichier :** `docs/devops/vps-preprod.md`
- Paquets (Ubuntu 24.04, MariaDB 11.4 du dépôt officiel, ffmpeg obligatoire), utilisateur et droits, base et compte de sauvegarde,
  première installation, nginx/HTTPS/PHP-FPM, déploiement par GitHub (clé, sudoers, secrets), sauvegardes et restauration,
  vérifications après mise en ligne.

## Problemes rencontres (si applicable)
- Les variables d'environnement du conteneur PHP passent avant `.env.test` : `<env … force="true"/>` dans `phpunit.dist.xml`
  (`<server>` ne suffit pas, Symfony lit `$_ENV` en premier).
- CSRF sans état : pour le test de bout en bout avec curl, il faut le cookie `csrf-token_<jeton>`, un jeton d'au moins
  24 caractères et l'en-tête `Origin`.
- `rsync -a` recopie la date du dossier source sur l'instantané : `touch` ajouté, sinon la rotation supprimait des sauvegardes récentes.
- `composer validate --strict` exige `name` et `description`, utiles seulement pour Packagist : `--no-check-publish`.
- Première version : déploiement automatique à chaque push sur `main`. Retiré à la demande de l'utilisateur :
  la mise en ligne est désormais une action volontaire.
