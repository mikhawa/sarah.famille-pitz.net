# Phase 6.5 : Procédures de production adaptées à AlmaLinux 9

> Date : 28 octobre 2026, 17 h 26

## Objectif
Le VPS tourne sous AlmaLinux 9 : adapter la procédure nginx + PHP-FPM (écrite pour Ubuntu) et compléter la
procédure CyberPanel.

## Actions realisees

### 1. Paquets
**Fichier :** `docs/devops/vps-preprod.md`
- AlmaLinux 9 n'a ni PHP 8.3, ni MariaDB 11.4, ni ffmpeg dans ses dépôts de base : EPEL + CRB, Remi
  (`dnf module enable php:remi-8.3`), RPM Fusion « free » (ffmpeg), dépôt officiel MariaDB.
- Commandes de vérification : version de PHP, extensions, WebP/JPEG dans GD, ffmpeg, MariaDB, nginx.

### 2. Utilisateur, pare-feu, SELinux
**Fichier :** `docs/devops/vps-preprod.md`
- `useradd` (pas d'`adduser` Debian), nginx ajouté au groupe `sarah` (et non `www-data`).
- firewalld : services `http` et `https`.
- SELinux laissé actif : contextes `httpd_sys_content_t` (site) et `httpd_sys_rw_content_t` (`var/`), booléens
  `httpd_can_network_connect_db` (MariaDB) et `httpd_can_network_connect` (SMTP) ; `ausearch` pour diagnostiquer.

### 3. nginx et PHP-FPM
**Fichiers :** `docs/devops/prod/nginx-sarah.conf`, `docs/devops/prod/php-fpm-sarah.conf`
- Chemins RHEL : `/etc/nginx/conf.d/`, `/etc/php-fpm.d/`, socket `/run/php-fpm/sarah.sock`, service `php-fpm`.
- `listen 443 ssl http2` : la directive `http2 on;` n'existe qu'à partir de nginx 1.25.1 (AlmaLinux 9 : 1.20 ou 1.24).
- Sessions PHP dans `var/sessions` : le dossier par défaut (`/var/lib/php/session`) appartient au groupe `apache`,
  inaccessible au pool qui tourne sous `sarah`.
- Certificat : configuration HTTP minimale pour le défi Let's Encrypt, puis configuration complète ; `certbot-renew.timer`.

### 4. CyberPanel sous AlmaLinux 9
**Fichier :** `docs/devops/cyberpanel.md`
- Installation de ffmpeg par RPM Fusion, extensions `lsphp83-*` par `dnf`, vérification de SELinux.
